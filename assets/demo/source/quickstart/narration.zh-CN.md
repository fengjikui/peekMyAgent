# 《五分钟第一次看清 Agent 工具闭环》旁白母稿

> 状态：中文故事 v0.3；等待所有者审阅后再冻结配音稿。
>
> 目标时长：约 4 分 15 秒。
>
> 画面：Codex 主题、2048×1056 真实 PMA Viewer 原始帧；命令使用明确标注为说明页的网页卡片。
> 场景：完全虚构的 `hello-agent` 项目和确定性本地 OpenAI Responses 上游，不使用真实账号、API Key、用户文件或网络。

## 教学合同

- **给谁看**：第一次接触 PMA、已经能正常使用一种 Agent / Harness 的用户。
- **只回答一个问题**：怎样从安装开始，第一次捕获并复盘“用户请求 → 工具调用 → 工具结果 → 最终回答”？
- **看完能复述**：PMA 不替代 Agent；它把 Agent 与模型之间的多次请求、工具交换和原始协议整理成一条可追溯证据链。
- **本章不讲**：Skill、子 Agent、上下文压缩、复杂协议兼容和异常排查；这些进入后续独立章节。
- **安全边界**：完全权限参数属于 Harness，不属于 PMA；只在可信的一次性测试目录中使用。

## 00｜开场：普通日志少了什么（00:00–00:18）

普通日志只会告诉你“Agent 调用了工具”。PMA 不替代 Agent；它把模型收到的上下文、工具调用、结果回传和原始协议串成一条可追溯证据链。接下来只用一个查看目录、读取 README 的最小任务，走完第一次完整复盘。

## 01｜安装并打开本地 Viewer（00:18–00:37）

先确认 Node.js 二十四或更新版本，然后安装公开预览版。`pma doctor` 检查命令、路径和本地服务，`pma open` 启动并打开只监听环回地址的 Viewer。PMA 的页面不应该直接暴露到公网。

## 02｜在安全目录启动一个 Agent（00:37–00:58）

准备一个只放虚构内容的测试目录，再选择你正在使用的一个 Harness。这里以 Codex CLI 为例。完全权限参数会跳过 Codex 的审批与 sandbox，只为了让公开演示不中断；它不是 PMA 的提权开关，也绝不能直接用于不信任的仓库。

## 03｜先看完整工具闭环（00:58–01:22）

任务没有业务门槛：查看目录，读取 README 的项目目标，最后用一句话说明用途。确定性轨迹一共有三次模型请求。PMA 的机制流程把它整理成：用户请求、列目录、目录结果回传、读文件、文件结果回传和最终回答。先看完整链，再进入细节。

## 04｜模型一开始收到了什么（01:22–01:46）

点击第一条请求旁的“详情”，右栏由这里打开。再切到 System，可以看到该次请求真正携带的指令，而不是 PMA 根据最终行为猜出的总结。同一排还可以继续查看 Developer、Tools、History、Message 和 Metadata。

## 05｜工具结果怎样回到模型（01:46–02:09）

现在点击第二次请求里的 `list_directory` 工具结果，再选择右栏的 `tool_result`。这里保留实际回传的目录清单和调用标识。工具是在本地 Harness 中执行的；下一次模型请求收到的是 Harness 封装后的结果，不是模型自己读取了磁盘。

## 06｜从结果返回来源调用（02:09–02:31）

结果旁的“来源 #1”不是装饰。点击后，PMA 跳回产生这份结果的 `list_directory` 调用，并在顶部提示当前正在查看来源。右栏显示工具名、调用标识和参数；“返回结果 #2”可以回到刚才的结果。长轨迹里不必手工来回翻找。

## 07｜最终回答是否真的有证据（02:31–02:50）

最后点击最终回复旁的“详情”，再看 Response。回答说这个项目用于演示 Agent 查看目录、读取文档并依据工具结果作答。现在可以沿同一条时间线核对：这个结论是否真的来自 README 的工具结果。

## 08｜摘要不够时回到协议（02:50–03:16）

需要精确字段时，切到“协议视图”。这里明确显示 OpenAI Responses、模型名称、instructions、工具声明，以及上行消息、工具调用和工具结果的原生顺序。摘要帮助阅读；协议视图和完整请求负责让你核对 Harness 有没有漏传、改写或排错位置。

## 09｜长会话为什么需要两级导航（03:16–03:41）

真实任务很快就会变长。右侧竖向 Turn Rail 先定位用户任务进行到哪一轮；当当前 Turn 至少包含五次主线 Request 时，中栏顶部出现 Request Rail，继续定位这一轮内部的模型往返。推荐顺序是先选 Turn，再选 Request。

## 10｜停止与清理不是一回事（03:41–04:02）

退出被 PMA 启动的 Agent 后，当前 watch 会停止，已经捕获的 Trace 仍然保留。`pma shutdown` 只停止本地 dashboard 服务，不删除历史。只有确认所有会话都不再需要时，才执行 `pma clear --all-sessions`；这是永久清空操作。

## 11｜收束（04:02–04:15）

现在你已经完成第一次闭环：启动原 Agent，在 PMA 中找到请求，追踪工具结果，再回到协议证据。下一步可以分别学习工具迟到回传、Skill、子 Agent、上下文变化和自研 Harness 接入。

- `peekMyAgent` 首次读作“peek my agent”，后续简称字母 “P M A”。
- `Codex CLI`、`System`、`Developer`、`Tools`、`History`、`Message`、`Metadata`、`Response`、`Turn`、`Request`、`Harness` 保留英文原写法。
- 配音友好稿可把 `pma` 命令读作字母，但屏幕字幕和文档继续保留真实命令。
- 翻译其他语言时只替换说明卡、旁白和字幕，不修改真实 Viewer 原始帧；应重新录制对应 UI 语言版本。
