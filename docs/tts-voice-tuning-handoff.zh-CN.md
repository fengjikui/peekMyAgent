# PMA 中文主讲人音色探索交接

本文交给一个独立任务，专门逐轮寻找 PMA 中文产品视频的主讲人音色。它不负责 Viewer 截图、视频剪辑、产品功能、协议适配或 Bug 修复。

## 当前结论

截至 2026-08-01，仓库中已经生成的 MiMo 中文试听全部未入选。不要把任何现有样本当作接近定稿的基线，也不要直接生成整片旁白。

产品所有者对当前试听的反馈：

- “茉莉”比其他初始方向稍可接受，但部分句子情绪起伏过大，语速偏慢；
- 后续稳定、加速版本仍不够好听；
- Voice Design 的“清透知性”“轻台湾语调”“明亮轻磁性”六条样本听起来都不舒服；
- 不需要台湾腔。“台湾甜妹”只是剪映中恰好调得比较自然、悦耳的参考音色，不是要复制的口音或身份；
- 当前最重要的是先找到能连续承担产品介绍的声音，而不是为现有视频赶工。

## 目标听感

目标是一位适合开发者产品演示的中文女性主讲人：

- 第一听感自然、舒服、容易继续听，不像模型在“表演一个音色”；
- 普通话自然，不指定台湾腔、方言或地域身份；
- 中等偏快，但不抢字、不吞英文术语；
- 情绪稳定、轻微积极，句与句之间没有突然拔高、压低或制造悬念；
- 亲和、可信、有一点年轻感，但不甜腻、不撒娇、不使用广告腔或纪录片腔；
- 连续听 45～60 秒不会疲劳；
- `Claude Code`、`PMA`、`Agent`、`tool use`、`tool result` 等技术词清楚。

明确排除：刻意的气声、尖亮高音、过强前置共鸣、甜妹表演、播音腔、预告片悬念、拖长句尾、情绪台阶和为了“高级感”而刻意压低声音。

## 为什么上一轮可能失败

上一轮 Voice Design 使用了“中高音区、清透偏凉、前置共鸣、轻微磁性、字尾收束”等声音工程词。提示并不算短，但可能规定了太多可被夸张表演的局部特征，结果听起来造作。下一轮不要默认“更长、更细的提示一定更好”。

需要分别判断两个问题：

1. 基础音色本身是否悦耳；
2. 同一个音色的语速、情绪、停顿是否合适。

导演模式、自然语言指令和音频标签主要解决第二个问题。它们不能保证把一个不喜欢的基础音色调成喜欢的声音。

## MiMo 能力层级

MiMo V2.5 TTS 有三条模型路线：

- `mimo-v2.5-tts`：预置音色；
- `mimo-v2.5-tts-voicedesign`：用文字设计新音色；
- `mimo-v2.5-tts-voiceclone`：用有合法授权的 WAV/MP3 样本固定音色。

导演模式不是第四种模型，而是自然语言风格控制的结构化写法。预置音色和 Voice Clone 还支持句内音频标签；Voice Design 不支持句内音频标签。完整事实以 [MiMo 官方 Skill](https://github.com/XiaomiMiMo/MiMo-Skills/blob/main/skills/mimo-v2-5-tts/SKILL.md)和[官方 TTS 文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5)为准。

官方 Skill 建议几乎所有不超过 2500 个汉字的长文本一次生成。短样选声阶段使用 2～5 句；正式音色选定后，再一次生成 45～60 秒连续讲解验证稳定性。

## 权利与隐私边界

- 不得把剪映“台湾甜妹”生成音频上传到 MiMo Voice Clone；目前没有证据证明剪映授权允许跨平台复制其商业预置音色。
- 剪映参考音频只能供产品所有者内部比较悦耳度、节奏和自然度。
- Voice Clone 只能使用产品所有者拥有权利的真人录音，或从 MiMo Voice Design 中已经入选的原创生成样本。
- API Key 只存在被 Git 忽略的 `.env.mimo.local`，不得打印、复制到文档、配方、日志、字幕或产物。
- 所有试听文本使用非敏感、虚构的 PMA 演示内容。

## 下一任务的工作节奏

每轮最多生成三条 10～20 秒样本，然后停止并等待产品所有者反馈。一次只比较一个变量：

1. 先用非常短、口语化的指令重新测试基础音色，不写共鸣位置、音高和声学术语；
2. 同一文本、同一模型和同一音色生成两个 take，避免把随机差异误当成提示效果；
3. 只有基础音色得到“愿意继续听”的反馈后，才测试语速、停顿和情绪；
4. 只有 10～20 秒通过后，才生成 45～60 秒连续讲解；
5. 只有长听感通过后，才保存样本并进入 Voice Clone；
6. 如果 MiMo 连续两轮仍没有明显改善，暂停 MiMo，记录结论；最终音频继续使用剪映已授权音色，不为了自动化牺牲成片听感。

不要使用音频理解模型替产品所有者评价“是否好听”。ASR 只检查术语可辨识度，时长和响度工具只检查客观质量。

## 固定试听文本

显示字幕：

> 现在，我们来看一次 Claude Code 的工具调用。打开 PMA，请求、工具调用和模型回复，都在同一条时间线上。

TTS 朗读稿：

> 现在，我们来看一次克劳德 Code 的工具调用。打开 P M A，请求、工具调用和模型回复，都在同一条时间线上。

屏幕字幕始终保留标准拼写；`克劳德 Code` 只用于提高 TTS 可辨识度。

## 完成条件

只有产品所有者明确选中一条声音，并且该声音通过 45～60 秒连续讲解试听，才能把音色探索标记为完成。仅仅生成更多样本、ASR 正确或提示词更详细都不算完成。
